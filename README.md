# TELEGRAM MARKET — فروشگاه تلگرامی (aiogram 3 + FastAPI + MongoDB + Railway)

فروش **Telegram Stars / Premium / Gifts** با پرداخت Stars، پنل ادمین مرورگری، قیمت‌گذاری با سقف سود ۷٬۰۰۰ تومان.

## تحویل چطور کار می‌کند (محدودیت واقعی API تلگرام)
| محصول | تحویل | چرا |
|---|---|---|
| **Premium** (۳/۶/۱۲ ماه) | **خودکار** با `giftPremiumSubscription` | API رسمی؛ از موجودی Stars **ربات** پرداخت می‌شود (۱۰۰۰/۱۵۰۰/۲۵۰۰ Star) |
| **Gift** | **خودکار** با `sendGift` | API رسمی؛ قیمت و موجودی (برای گیفت‌های محدود) را خود تلگرام می‌دهد |
| **Stars** | **دستی** (قانون ۵۰ به بالا آماده است ولی فعلاً هیچ روش رسمی ارسال وجود ندارد) | Bot API راهی برای فرستادن Star ندارد. سفارش «نیازمند تحویل دستی» می‌شود، به شما پیام می‌آید و در پنل «تحویل شد» را می‌زنید |

- گیرنده محصول خودکار همان خریدار است. موجودی Stars ربات از پرداخت مشتری‌ها پر می‌شود؛ اگر کم باشد تحویل «ناموفق» می‌شود و بعد از پر شدن از پنل «تلاش مجدد» می‌زنید.
- **تحویل خودکار Stars (≥ ۵۰):** طبق مستندات رسمی، Bot API متد ارسال Star ندارد و در MTProto فقط «خرید Stars برای دیگری با پرداخت پولی» هست، نه انتقال از موجودی Star اکانت شما. پس هیچ ارسال‌کننده‌ای فعال نیست و همه‌ی سفارش‌های Stars امن دستی می‌مانند. کد `stars_delivery.py` آماده‌ی پلاگ‌کردن یک روش رسمی در آینده است (حداقل Star از پنل، چک موجودی قبل از پرداخت و قبل از ارسال، عدم ارسال دوباره، علامت‌گذاری نتیجه‌ی نامشخص برای ادمین). ارسال شبیه‌سازی‌شده وجود ندارد.
- **MTProto / ورود با اکانت شخصی پیاده نشده**: نیاز به Session دارد، خطر بن شدن اکانت دارد و اینجا قابل آزمایش نبود. هیچ کد ورود یا Session نباید جایی گذاشته شود.
- اگر نتیجه ارسال نامشخص باشد (قطع شبکه)، سفارش **هرگز خودکار دوباره ارسال نمی‌شود**؛ می‌رود به تحویل دستی تا خودتان بررسی کنید.

## راه‌اندازی روی Railway
1. BotFather → `/newbot` → توکن.
2. پروژه را روی GitHub بگذارید (`.env` را آپلود نکنید) → Railway → Deploy from GitHub.
3. در همان پروژه: New → Database → **MongoDB**.
4. Variables را از `.env.example` (بخش «ضروری») پر کنید. `MONGODB_URI=${{MongoDB.MONGO_URL}}`.
5. Settings → Networking → **Generate Domain**. سرویس باید **۱ replica** بماند.
6. دامنه → `/login` → ورود با ادمین اولیه.
7. پنل > **قیمت‌گذاری**:
   - «ثبت نرخ دلار دستی» (یا `RATE_API_URL` را تنظیم کنید).
   - «ارزش هر Star برای مشتری (دلار)» و «قیمت خرید هر Star برای شما (دلار)» را بنویسید. این اعداد را تلگرام نمی‌دهد و جایی هاردکد نشده.
   - سود پیش‌فرض (۰ تا ۷۰۰۰).
8. پنل > **محصولات**: «ساخت پکیج‌های Premium» و «دریافت گیفت‌ها از تلگرام» را بزنید. محصولات **غیرفعال** ساخته می‌شوند؛ قیمت‌شان را ببینید و فعال کنید. برای Stars با «افزودن محصول» بسازید (نوع Stars، مقدار = تعداد Star).
9. **اول با ارزان‌ترین گیفت و یک خرید کوچک واقعی تست کنید** (پرداخت، تحویل، بازپرداخت).

## روش‌های پرداخت و قانون تلگرام
طبق [مستندات رسمی تلگرام](https://core.telegram.org/bots/payments-stars) محصول دیجیتال داخل ربات **فقط با Stars** پرداخت می‌شود و درگاه/ارز دیگر مجاز نیست (تلگرام ممکن است ربات را برای کاربران موبایل نمایش ندهد). Stars/Premium/Gift دیجیتال‌اند، پس **زرین‌پال و کارت‌به‌کارت برای آن‌ها پیاده‌سازی نشده‌اند**. ساختار آماده است: `payment_base.py` توضیح می‌دهد چطور یک درگاه تازه (یک فایل `payment_<name>.py` با `external = True`) اضافه شود؛ `payment_manager.py` به‌صورت مرکزی هر روش `external` را برای محصول دیجیتال پنهان می‌کند.

## قیمت‌گذاری
- قیمت فروش = قیمت خرید + سود (۰ تا ۷٬۰۰۰ تومان)، با گرد کردن تنظیمی.
- قیمت خرید: Premium/Gift از تلگرام (به Star) × «قیمت خرید هر Star»؛ Stars و سایر محصولات دستی.
- **مبلغ Stars که مشتری واقعاً می‌دهد هم داخل سقف سود ۷۰۰۰ نگه داشته می‌شود** (نه فقط قیمت تومانی).
- نرخ دلار: خودکار از `RATE_API_URL` (اگر تنظیم کنید) یا دستی. نرخ خودکار بعد از «حداکثر عمر» (پیش‌فرض ۱۲۰ دقیقه) و نرخ دستی بعد از ۲۴ ساعت، **فروش را متوقف می‌کند**؛ همین برای داده‌های تلگرام هم هست.
- کلید «به‌روزرسانی خودکار» را از پنل می‌توانید خاموش کنید. قیمت هر سفارش در لحظه ثبت ثابت می‌شود (`price_snapshot`).

## پنل ادمین
محصولات (جدا برای Stars/Premium/Gifts: افزودن، ویرایش، فعال/غیرفعال، موجودی، قیمت خرید/فروش، آخرین به‌روزرسانی)، قیمت‌گذاری، سفارش‌ها (فیلتر وضعیت پرداخت/تحویل/«نیازمند تحویل دستی»، صفحه‌ی جزئیات با تاریخچه، خطاها در صفحه‌ی «خطاها»، تحویل شد، تلاش مجدد، لغو و بازپرداخت Stars)، تأمین و تحویل (وضعیت تلگرام، موجودی Stars ربات، خطاها)، پرداخت‌ها، کیف پول، کاربران، تیکت‌ها، لاگ.
موجودی خالی = نامحدود؛ عدد = رزرو هنگام ساخت سفارش و برگشت در صورت انقضا/لغو/بازپرداخت تحویل‌نشده.

## اجرای محلی و تست
```
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
docker run -d -p 27017:27017 mongo:7
uvicorn main:app --reload
pytest
```

## وضعیت تست (واقعاً اجرا شده)
`pytest`: **۱۲۲ تست موفق** با دیتابیس شبیه‌سازی (mongomock) و ربات جعلی: قیمت‌گذاری، سقف سود، انبار، پرداخت Stars، pre-checkout، تکراری، تحویل خودکار/دستی، شکست و تلاش مجدد، بازپرداخت، پنل وب، قانون ۵۰ Stars با ارسال‌کننده‌ی آزمایشی (فقط تست، نه ارسال واقعی).
**اجرا نشده:** اتصال واقعی به Telegram (متدهای Gift/Premium/موجودی)، پرداخت واقعی، Mongo واقعی و همزمانی، `RATE_API_URL` واقعی.

## محدودیت‌های شناخته‌شده
- Stars دستی است. پرداخت با Stars برای خرید Stars منطق اقتصادی ندارد مگر مشتری‌ها Stars را ارزان‌تر از ارزش آن بگیرند؛ این تصمیم تجاری با شماست.
- پرداخت با کیف پول پیش‌فرض غیرفعال است و بازپرداخت فقط برای پرداخت Stars است.
- FSM ربات در حافظه است. TON غیرفعال است. کد تخفیف و سبد چندمحصولی نیست.
- بکاپ: `mongodump` از Railway.
