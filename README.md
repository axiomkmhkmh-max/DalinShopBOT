# TELEGRAM MARKET — فروشگاه تلگرامی (aiogram 3 + FastAPI + MongoDB + Railway)

ربات تلگرام برای فروش محصولات دیجیتال (Premium / Stars / Gifts) با:
پرداخت **Telegram Stars (XTR)**، قیمت‌گذاری خودکار (سود حداکثر ۷٬۰۰۰ تومان)، پنل ادمین مرورگری، کیف پول با دفتر کل، تیکت پشتیبانی.
فقط ربات تلگرام برای مشتری؛ بدون Mini App و بدون سایت مشتری.

## ⚠️ وضعیت واقعی پروژه (صادقانه)

| مورد | وضعیت |
|---|---|
| تست‌های محاسبه قیمت، گرد کردن، سقف سود، ریال→تومان، ماشین وضعیت، نقش‌ها | **اجرا شد (۱۴ تست موفق)** با یک runner ساده در محیط ساخت |
| تست‌های دیتابیس‌دار (Stars، تکراری، تحویل ناموفق، کیف پول، نرخ منقضی، snapshot قیمت) | **نوشته شد ولی اجرا نشد** (در محیط ساخت pytest/mongomock نصب نبود) |
| کد ربات aiogram، پنل FastAPI، اتصال Mongo | **فقط compile/syntax-check شد؛ اجرا نشده** |
| پرداخت واقعی Stars | **تست نشده.** باید با ربات واقعی خودتان امتحان کنید (قدم‌ها پایین) |
| TON و درگاه ایرانی | **غیرفعال** (فقط Adapter و توضیح شرایط) |
| Mock Payment | فقط توسعه؛ در `APP_ENV=production` همیشه رد می‌شود |

قبل از فروش واقعی، دستور `pytest` را اجرا کنید و با یک خرید کوچک واقعی Stars چرخه کامل را تست کنید.

## قانون تلگرام و روش‌های پرداخت
برای محصولات دیجیتال داخل ربات، **فقط Stars** فعال است. TON و درگاه ایرانی برای این محصولات هرگز به مشتری نشان داده نمی‌شوند
(`app/payments/manager.py`) و راه دور زدن ساخته نشده. فایل‌های `ton.py` و `iran_gateway.py` شرایط لازم برای فعال‌سازی
(مجوز، قرارداد، API رسمی، تأیید سرور) را در توضیح بالای فایل نوشته‌اند. این دو فقط برای محصول/سرویس مستقلی که طبق قوانین تلگرام و قانون کشور مجاز به پرداخت بیرونی باشد قابل استفاده‌اند.

## راه‌اندازی روی Railway (قدم‌به‌قدم)
1. در BotFather: `/newbot` → توکن را نگه دارید. (Stars نیاز به provider token ندارد.)
2. پروژه را روی GitHub بگذارید (فایل `.env` را هرگز آپلود نکنید).
3. Railway → New Project → Deploy from GitHub → همین ریپو.
4. در همان پروژه: New → Database → **MongoDB**.
5. روی سرویس برنامه → Variables:
   - `APP_ENV=production`
   - `BOT_TOKEN=` توکن BotFather
   - `MONGODB_URI=${{MongoDB.MONGO_URL}}` (نام سرویس دیتابیس شما ممکن است فرق کند)
   - `WEBHOOK_SECRET=` یک رشته تصادفی فقط با حروف انگلیسی/عدد/`_`/`-`
   - `SESSION_SECRET=` رشته تصادفی حداقل ۳۲ کاراکتر
   - `ADMIN_BOOTSTRAP_USERNAME=owner` و `ADMIN_BOOTSTRAP_PASSWORD=` رمز حداقل ۱۰ کاراکتر
   - `ADMIN_ALERT_CHAT_IDS=` آیدی عددی تلگرام خودتان (برای هشدار خطا)
6. Settings → Networking → **Generate Domain**. دامنه خودکار با `RAILWAY_PUBLIC_DOMAIN` شناخته می‌شود و webhook خودکار تنظیم می‌شود.
7. سرویس باید روی **۱ replica** بماند (ربات، پنل و کارهای پس‌زمینه در یک پروسه‌اند).
8. آدرس دامنه را باز کنید → `/login` → با ادمین اولیه وارد شوید. بعد از ورود، رمز را در `.env`/Variables عوض نکنید؛ ادمین جدید فقط وقتی ساخته می‌شود که هیچ ادمینی نباشد.

### داده اولیه
محلی: `python -m scripts.seed` (دسته‌بندی/محصول نمونه + تأمین‌کننده دستی). یا همه چیز را از پنل بسازید.

## راه‌اندازی پرداخت Stars (خلاصه)
1. توکن ربات را در Variables بگذارید. 2. در پنل > قیمت‌گذاری مقدار **«ارزش هر Star برای مشتری (USD)»** را خودتان وارد کنید (تلگرام API رسمی برای این نرخ نمی‌دهد؛ هیچ عددی هاردکد نشده).
3. یک محصول بسازید، قیمت پایه و منبع نرخ را تنظیم کنید. 4. با یک اکانت دیگر یک خرید کوچک انجام دهید و در پنل > پرداخت‌ها وضعیت `SUCCEEDED` را ببینید.
5. بازپرداخت: پنل > سفارش‌ها > «بازپرداخت Stars» (نقش Owner/Finance).

## قیمت‌گذاری خودکار
- فرمول: `قیمت نهایی = هزینه پایه (تومان) + سود` ؛ سود ۰ تا ۷٬۰۰۰ تومان (هم در پنل و هم در کد اعمال می‌شود). اگر گرد کردن باعث عبور از سقف سود شود، گرد کردن کاهش داده می‌شود.
- ارز پایه IRT/IRR تبدیل ارز ندارد (ریال ÷ ۱۰ دقیق). سایر ارزها × نرخ تومان.
- **منبع قیمت پایه**: برای هر محصول «دستی» یا «Price Provider». **منبع نرخ ارز**: Rate Provider. هر دو از env/تنظیمات (`http_json`) و قابل تعویض‌اند؛ آدرس و JSON-path را خودتان از یک تأمین‌کننده واقعی وارد می‌کنید (نمونه در `.env.example`). کلیدها فقط در env.
- نرخ هر ارز یک‌بار در هر چرخه گرفته می‌شود (نه برای هر محصول). حداقل بازه به‌روزرسانی ۵ دقیقه.
- نرخ/قیمت قدیمی‌تر از «حداکثر عمر» → محصول **قابل خرید نیست** (قیمت قدیمی هرگز به‌عنوان قیمت زنده نمایش داده نمی‌شود). حالت «نیازمند تأیید ادمین» پیاده‌سازی نشده؛ فقط توقف خرید.
- قیمت هر سفارش هنگام ثبت در خود سفارش (`price_snapshot`) ذخیره می‌شود.
- هنوز به **API Key / تأمین‌کننده واقعی** نیاز دارند: قیمت پایه (برای محصولات provider)، نرخ USD→تومان (و TON اگر لازم)، و تأمین‌کننده تحویل (Premium/Stars/Gift).

## اجرای محلی و تست
```
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env     # مقادیر را پر کنید
docker run -d -p 27017:27017 mongo:7
uvicorn app.main:app --reload
pytest
```
بدون `PUBLIC_BASE_URL` ربات با long polling اجرا می‌شود.

## طراحی مالی (خلاصه)
- سفارش قبل از فاکتور ساخته می‌شود؛ pre-checkout مبلغ/کاربر/انقضا را چک می‌کند؛ successful_payment دوباره اعتبارسنجی می‌شود.
- وضعیت `PAID` فقط با یک compare-and-set اتمی؛ شناسه پرداخت تلگرام کلید یکتای رکورد پرداخت (`stars:<charge_id>`) است → پرداخت/به‌روزرسانی تکراری بی‌اثر.
- تحویل فقط برای سفارش PAID و با claim اتمی (`PAID→PROCESSING`)؛ هر سفارش حداکثر یک رکورد تأمین‌کننده.
- شکست تحویل: سفارش `FAILED`، پیام به مشتری «نیازی به پرداخت مجدد نیست»، هشدار به ادمین، تلاش مجدد از پنل بدون پرداخت دوباره.
- کیف پول: مبلغ‌ها عدد صحیح تومان، دفتر کل فقط‌افزودنی با کلید یکتا؛ کسر با شرط اتمی `balance >= amount`.

## محدودیت‌های شناخته‌شده
- Mongo روی Railway معمولاً تک‌نود است؛ تراکنش چنداسنادی فرض نشده. ترتیب «به‌روزرسانی شرطی موجودی → ثبت دفتر کل → جبران در صورت خطا» استفاده شده؛ `wallet.reconcile` برای تطبیق هست. تست همزمانی واقعی روی Mongo واقعی انجام نشده.
- شارژ کیف پول با Stars پیاده‌سازی نشده (کیف پول فقط با تعدیل ادمین/جایزه دعوت/بازپرداخت داخلی پر می‌شود) و پرداخت با کیف پول به‌طور پیش‌فرض غیرفعال است.
- سبد خرید چندمحصولی، کد تخفیف، تحلیل رفرال و گزارش مالی کامل پیاده‌سازی نشده‌اند (کد تخفیف در ربات پیام «غیرفعال» می‌دهد).
- هشدار/بازپرداخت خودکار برای پرداخت دیررس (سفارش لغوشده) نیست؛ رکورد `NEEDS_REFUND` ثبت و ادمین مطلع می‌شود.
- بکاپ: از Railway/Mongo (`mongodump`) استفاده کنید.
- FSM ربات در حافظه است (با restart پاک می‌شود).
